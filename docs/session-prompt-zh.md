我是 Metrolinx 市场部的数据科学家，负责客户洞察、票价策略和客流预测。我想做一个研究：**用卫星雷达数据，重建 GO 火车站停车场 2018–2026 年的使用情况**，因为 GO 只公布停车场的容量，没有占用率，也没有历史记录，露天停车场里更没有传感器。

**核心想法**

用 Sentinel-1 合成孔径雷达（SAR）的 VV 后向散射强度作为停车需求的代理指标。原理是：光滑沥青像镜子，把雷达波反射走，空停车场很“暗”；车身是金属，和地面形成角反射，把雷达波弹回来，满停车场就“亮”。一个停车场的平均 VV 随时间连起来，就是一条长期需求趋势线。

**已完成的工作**

1. **试点**：选了 Oakville、Clarkson、Bronte 三个站，共 6 个露天 lot。每个露天 lot 单独一个 polygon，室内停车楼全部排除（SAR 看不到楼里）。polygon 是我自己在卫星图上画的，已验证闭合、无自交、无重叠，每车位 27–32 平方米，内部通道包括在内是合理的。Oakville Main 2,712 个车位、South 291 个；Clarkson Main 1,274 个、North 627 个（GO 官网数，已由 Parkopedia 的 1,020 修正）；Bronte Main 1,824 个、South 1,149 个。Clarkson North 的 polygon 是 52 平方米/车位，边界待复核。

2. **快速信号验证**：用微软 Planetary Computer 的 Sentinel-1 RTC 数据（γ⁰），52 景升轨，2019、2020、2024 三个夏天对比。结果是 6 个 lot 在 2020 年夏天比 2019 年都掉了 0.8–2.0 dB（Oakville Main -1.56 dB，Clarkson North -2.00 dB），2024 年 6 个里有 5 个恢复到 2019 年上下 0.3 dB 以内。信号是真实存在的，但 dB 换不成占用率百分比，没有地面真值标定。

3. **全网清点**：71 个火车站，57 个有免费停车，14 个没有；69,338 个车位，其中露天 57,606 个（83.1%）、车库 11,732 个（16.9%），共 96 个 lot。Bloomington 和 Centennial 是 100% 车库，VV 做不了；18 个 lot 小于 200 个车位，信号弱。

**关键限制，必须写进任何报告里**

- Sentinel-1 在 Oakville 只有升轨陆地成像，过境时间是夏天 19:08–19:16、冬天 18:08–18:16，测的是**晚高峰尾巴上的残余量**，不是峰值占用率，夏天和冬天不能直接比。
- dB 是相对指数，只能讲趋势、排名和恢复程度（2019 年 = 100），不能直接说“占用率是多少”或“需要建多少个车位”。
- 只看露天，车库看不见；坏天气把车赶进车库时，露天 VV 会掉，但全站需求未必掉了。

**我想回答的业务问题**

这不是换个数据源重讲客流恢复的故事。PRESTO 告诉我总客流恢复了多少，我要回答的是 PRESTO 回答不了的：**开车来坐车的人恢复得怎么样？和总客流的分叉在哪里？** 这个分叉决定预算是投给停车场扩建，还是投给接驳公交；也决定哪个长期闲置的 lot 可以开发，哪个长期饱和的 lot 要优先复核。一个停车楼要 4,000–4,700 万加元，这个判断的价值就在于避免建错。

**下一步怎么做**

请按这个顺序帮我规划和执行：

1. 先用微软数据做一份**初步报告**，把时间扩到 2018–2026 所有夏天，输出每 lot 的年度恢复指数和图表，封面写清“初步验证、γ⁰、约 19:10 晚间残余指数”这三点。
2. 做**地面标定**，用历史光学影像或现场计数，在几个已知日期数车，建立 dB 到车数的换算关系，没有这一步不能报百分比。
3. 并行学 **SARpanel 正式链**（github.com/ryjayne89/sarpanel，锁定 a1c17c1 版本），先跑 2019 年夏天试跑，再跑全段，和微软的结果交叉验证。正式项目以 SARpanel 为主链，微软为副链，两条链的 dB 绝对值不要混成一条线。
4. 扩到**所有有露天停车场的 GO 车站**（57 个站、86 个露天 lot），草稿一次生成，复核按线分批做，跑完和 PRESTO 对出分叉表。
5. 最后做成**业务产品**：停车指数 vs PRESTO 客流的对比、恢复排名、给领导的一页简报，开头讲决策，不讲方法。

**不要做的事**：暂时不扩到加拿大其他城市，不在标定之前做仪表盘，不把 dB 直接说成占用率。
